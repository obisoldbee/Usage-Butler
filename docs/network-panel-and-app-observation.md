# 网络接口、后台应用观察与历史（0.5.0）

应用活动来自普通权限的系统 `/usr/bin/nettop -P -L 0 -n -x -s 1 -J bytes_in,bytes_out`。内嵌独立 helper 的 ProcessNetworkCollector 负责进程来源，主App通过有限IPC读取；IFMIB 接口来源保持独立；旧 flow 演示合同不参与 Release 应用统计。

## 用户界面

网络页的应用活动提供真实应用/进程列表、名称/进程搜索、上传/下载/名称排序、本次运行关注筛选、当前速率和各向本段累计。详情复用稳定坐标的原生双趋势，红上蓝下、五档时间、独立刻度与联动游标；返回保留查询、排序、返回行与键盘焦点。未知启动身份不支持关注。主面板健康时不重复显示采集开关或接口选择；设置页集中控制并分别描述接口与应用来源状态。

本地 JSON 先固定快照并展示别名化预览，再打开系统保存面板。取消不写文件。导出不含应用/进程名称、PID、路径、端点或凭据；连接数、协议与目标明确为 null。列表导出当前筛选集合及段累计；详情导出所选时间内实际保留的源点。编码大小上限 8 MiB，超限提示缩小范围。别名化不是匿名承诺。

## 来源与身份

应用详情直接显示上传、下载各自的累计起点与本地化原因，包括进程成员变化、完整采样不足、计数不可用或重置、累计溢出；不跳转到仅含接口累计诊断的设置区。应用与接口的累计始终分别解释。

这属于系统可见进程 socket 字节口径，可能计入回环、代理腿与重传，不是网卡线速或外网计费。接口与应用不得求和；不将代理的流量猜回原应用，不把进程行当成连接。短到没有进入 nettop 帧的进程没有覆盖保证。

源的标准输入、输出共用自有 PTY，父进程只读并持续排空，不发送交互输入；避免空输入设备的 EOF 导致子进程持续唤醒。重复 CSV 表头定义帧边界。时间是收到表头时的单调时钟，墙钟仅用于显示；下一表头确认前一帧，约有一秒分帧延迟。它不是内核精确事件时间。过快成批到达、超时、格式漂移、EOF、超大输出均明确不完整，不据发布时刻补造采样。

PID 与公开 proc_bsdinfo 的启动秒/微秒、proc_pidpath 路径共同建立实例。前后核对启动身份；可执行文件实际位于有效应用 Bundle 内时按规范化安装路径与 Bundle ID 归属辅助进程。不同安装路径独立；共享 WebKit/系统代理独立呈现。签名始终未验证，Bundle ID 不代表签名证据。身份读取和 nettop 不是内核原子快照；启动身份不可证实时，使用每帧独立未知观察，不能跨帧结算/关注。

## 结算与资源

CSV 只移除合法 CRLF 的末尾 CR；数字、名称或引号字段内部的 CR 属于无效控制字符，不拼接为有效计数。跨数据块的 CRLF 与超长行后的恢复仍受同一行上限控制。

自有 PTY slave 只关闭输出 `ONLCR` 转换，保留 stdin/stdout 的终端身份与其余输入/终端设置；避免生产者原有 CRLF 被驱动扩成 CRCRLF。配置失败以固定 `pty-config-failed` 原因结束来源并关闭自有描述符，不继续以未确认的 framing 运行。不修改系统或用户终端偏好，也不吞掉行内 CR。

进程 Core 与接口、图表共用 `NetworkChartSamplingContract` 的相邻声明周期缺口规则，使用前后两个可信周期中的较大者；未知或无效周期不能建立连续结算。实际 nettop 仍固定 1 Hz，来源的 0.5–2.5 秒到达节奏检查与健康补预算窗口的严格相邻规则保持独立。帧内求和及跨帧累计溢出都保留 `overflow` 原因，相应方向保持未知并重新起算，不饱和或补零。

速率只由源帧差值/单调时间结算；快照读取不推进基线。成员变化、PID 重用、缺行恢复、缺失方向、counter 下降、丢帧、长静默与源重启重新建立对应基线。各方向累计独立，可为空；不回填启动前字节。成功帧的缺行只表示当前源中未出现，不能推断进程已经退出。

每个helper会话一个 nettop；显式停止后台与休眠停止自有进程及 FD。主App正常退出只断开客户端，不停止已启用的helper。恢复创建新会话，保留有界历史但不跨会话结算。0.4.1 保留 2/4/6 秒退避和最多三次未稳定恢复的自动重试；同一会话内，已接受的完整、无 issue、连续序号、单调时间与相邻声明 cadence 一致的帧连续覆盖至少 60 秒后，补回预算。相邻真实间隔需同时满足两侧声明周期的 0.5–2.5 倍范围；partial、缺号、重发、乱序、旧会话、时间异常和不可信 cadence 重新开始健康窗口。单个好帧、UI 刷新和墙钟经过不补预算。确认临时读取/退出/超时故障耗尽快速预算后，helper按单调时钟5/10/20/30分钟低频恢复；稳定60秒源窗口重置。启动/配置/签名/授权错误、存储失败、停止、休眠和系统禁用不由该策略激活。用户仍可明确刷新，重新启用/休眠恢复也可开始新周期。所有跨等待恢复由 generation 和外部 intent revision 防止旧启用复活；主App管理接口电源意图，独立helper自行订阅系统电源通知；各collector内部代际守卫防止旧收尾覆盖新意图。开发重建脚本若用 SIGTERM，则另行核对并收尾该构建拥有的 nettop；不是按名称批量终止。

本地统一日志 category `ProcessNetworkLifecycle` 以 notice 级别只记录来源/collector 启停、重试安排或取消、预算耗尽、健康补回，不逐帧记录。内容是固定原因码及受限的尝试次数、退避秒数、退出类型/状态、清理动作、errno 和最后表头年龄；最初触发与本应用主动终止 child 的收尾动作分开。未知原因只写 unknown，不接受任意来源字符串。没有应用名称、PID、路径、目标、原始 CSV/stderr、环境或凭据，没有外发。日志保留由 macOS 管理，不承诺自有磁盘长期留存；新增诊断不能倒推此前未记录的退出原因。

上限：单行 4 KiB、单帧 stdout 1 MiB、stderr 总量 64 KiB、16 KiB 单次读取；源队列保留最新两帧，缺号必须重建基线；快照队列保留最新一个。每帧最多 2,048 进程、256 应用，身份元数据缓存 512 项/60 秒。helper每应用最近60个1Hz原始点，全局最多15,360点；客户端只接收当前行和一个已选应用的实时历史。更长五档范围读取磁盘分钟均速，真实采样峰值单列；优先淘汰最旧缺失应用。选择和关注不能突破预算。所有裁剪显式可见，停止后的定期保留清理仍有效。

接口侧同时统一相邻 cadence 的 gap 判断、源八事件/快照一项的缓冲上限、丢帧基线、显式休眠边界和全接口/旧会话的单调两小时清理。单调时钟回退不能作为跨未知时域的到期证据。

## 验证边界与后续

来源 poll 的等待上限为 100 ms；身份文件读取、调度与 child 回收可能更久，不能当作 stop 全路径期限。收尾等待自有 child 被回收后才交还所有权。生命周期日志的 cleanup 字段表示尝试的清理动作，exitKind/exitStatus 表示实际回收结果，二者可能不同。

导出 v1 保持原有字段集合；已有墙钟字段统一使用带三位小数秒的 UTC ISO8601（毫秒精度）。这用于保留亚秒采样和方向起点，不声明内核事件精度；单调纳秒、累计字节与序号仍保留为精确整数字符串，未知为 null。

独立 `usagebutler.network.process-export` v1 的根 `session` 表示当前源会话；每个历史点的 `session` 使用同一份导出内会话别名表，保留重启前历史的会话边界。`uploadContinuity` / `downloadContinuity` 仅在该点的 `session` 内有效，不能跨会话连接。`samplingIntervalSeconds` 保留已知的声明采样周期，未知为 null；实际时间差仍来自各点单调时间。应用与会话均为导出内别名，不输出原始应用 key、路径派生 hash、进程实例或原始会话 ID。

确定性测试、真实 TCP/UDP 回环、原生操作、资源 stress、Universal 构建分别记录，不能互相替代。受控回环的字节一致只证明该主机与该窗口；系统对照中的重传可解释部分差异，另有旧探针差异未解释，不作常数扣减。完整 VoiceOver、macOS 13/x86 实机、所有代理拓扑、真实 sleep/wake 与 18/24 小时浸泡没有执行。

NetworkExtension 的连接身份、目标与防护仍是独立能力门。没有安装系统扩展、提权、改网络、读取签名私钥或执行阻断。旧 flow 后端在正式 NE/ETW 接入前仍需独立审查，不因本次进程来源通过而取得真实执行资格。


## 独立后台与持久历史

设置中的“主程序退出后继续记录应用流量”控制内嵌SMAppService LaunchAgent；遵循系统批准状态和既有关闭偏好。服务只在当前登录用户上下文运行；不承诺注销、关机或休眠仍采集。主App无法连接时显示错误，不另起进程来源。退出说明区分主程序退出和停止后台。退出前异步清理具有一次性限时后备，超时记录drain未确认，不宣称全部本地写入成功；独立helper继续按原设置运行。

App与helper以本地代码签名designated requirement互相约束，并核对UID；升级用SMAppService异步unregister完成旧实例停止后重新注册。ad-hoc签名没有TeamID，也不是抵抗同用户修改文件的防篡改审计。这里的IPC代码验证不把观察到的其他应用BundleID提升为其签名证据。

打包时给helper使用稳定的显式签名identifier；App与helper使用同一签名身份，先签helper再签App，并做嵌套严格校验。注册返回成功只表示系统接受注册请求；必须在双向代码要求通过后核对实际helper版本、SHA256和进程路径，才保存已验证代码绑定。签名校验通过不能替代系统实际启动结果。

验证升级使用同一App路径、服务label与数据库：正常停止旧helper并等待SM异步注销，确认旧helper与其nettop退出，保留旧二进制证据，再替换App、递增构建号并重新注册，最后核对新helper及原历史记录。开发副本需避免同BundleID的过期App继续被LaunchServices识别。ad-hoc默认要求绑定cdhash，系统启动约束和开发缓存可能阻止换包；不以resetbtm、手工bootstrap或更换每个版本的产品label掩盖失败。Apple Development候选验证不是Developer ID分发或公证证明。

隔离验证App及其专属DB应放在不需要Documents文件隐私批准的位置；正式数据仍位于当前用户Application Support中的产品目录。受保护目录中的初始化等待、被拒绝的注册和签名失败应分别记录，不将它们统称为采集算法故障，也不自动修改TCC或系统后台批准。

私有目录0700、库/锁/sidecar0600。仅helper持有writer flock，拥有唯一nettop、SQLite writer和checkpoint。自有nettop启动身份及可执行路径用于异常遗留进程回收；PID复用或归属不符不发送信号。App在停止/未注册时可以对同一固定库做有界只读历史查询，缺库不新建、不迁移、不启动采集。

已接受的UInt64增量在发布节流前结算，按56字节二进制分钟记录保存：各向精确字节、观察微秒/样本数、真实采样峰值、边界和质量标记。小时摘要用于长范围汇总；查询边缘仍按完整分钟计算，不以比例拆分字节。未知身份仅计无法归属的源覆盖，不每天制造新应用目录。不可逆溢出保持该方向未知；不跨源会话、缺口、成员变化或墙钟跳变补造连续活动。

默认保留14天实际观察。连续单调年龄控制到期，跨boot未证实的离线时间保守多留。整段到期先持久标记查询不可见，再分块回收；中途异常可恢复清理，未到期基础记录不为容量被静默删除。正常约5帧/5秒提交，崩溃可能失去最后确认提交之后的数据；实际损失取决于调度和已提交时间。5秒是目标，不是所有故障的硬上限。

SQLite mmap关闭、page cache目标2MiB、临时数据使用文件；禁用未提交缓存spill并对脏页和提交前WAL预算检查。写事务缓存上限4MiB，WAL预算16MiB、主库加WAL512MiB；读锁导致软阈值checkpoint暂忙时允许短暂等待，预算不足则可见停写。活动最多50,000条，触顶只标记活动列表截断，基础分钟继续。身份/会话/段目录各有限，不能用内存保留全周。

历史位于显式打开的可调大小原生窗口，支持1小时/24小时/7天/14天、应用上传排序、每天UTC汇总和活动筛选。每页64行，曲线最多1440桶；分钟均速柱不表示分钟内连续。红上蓝下、独立纵轴、共享游标、固定/键盘及真实单位AX描述保留；归一化绘图使用固定刻度身份。关闭窗口取消过时查询并释放结果。

默认活动阈值是连续上传段100MiB，或连续60秒且每次采样至少100KiB/s。未知、零、来源重启、墙钟跳变、UTC日期边界切段，持续规则还在低于速率时结束。设置更改仅用于后续采样，旧活动保留当时规则。跨范围活动显示整段字节，与所选范围用量分开；这不是恶意、前台状态、文件内容或目标判断。

历史导出`application-network-history-v2`独立于v1，冻结当前范围/页，预览和保存期间不持有SQLite读事务；默认稳定应用分组别名，精确字节十进制字符串、覆盖与截断状态随附。IPC请求最多64KiB、实际编码响应最多4MiB；查询在独立只读executor上执行，单次约1秒预算，失败明确显示。

0.5.0的构建、测试、SM生命周期、受控流量和资源测量由绑定当前提交的验收记录分别证明。合成14天数据只证明规模，不能声称已连续运行两周；macOS13/Intel实机、真实睡眠/登录重启、完整VoiceOver与24小时运行未验。


## 0.5.2 身份次序、维护与连接边界

SQLite `user_version=2` 在分钟和小时桶各新增可空 `last_observation`。唯一 writer 为每个接受且非重放的源帧分配递增 Int64 序号，和桶、会话提交游标在同一事务保存；跨小时、session 和墙钟回退仍按接受顺序，分钟内 A→B→A 可显示最后的 A。每帧同一 stable key 不允许重复，不能从数组顺序制造同帧身份先后。序号溢出可见停写，不回绕。旧 56 字节 payload 和不可变应用身份、活动 provenance 保留。

v1→v2 原子迁移不回填次序；旧桶保持 NULL。查询只读支持 v1/v2，范围完全由旧证据组成时 `identityOrder=legacy-unverified`，显示的是明确标记的代表名称，不能称为最近身份。迁移后新观察序号可证明晚于迁移前所有旧观察，按所选桶/小时的最大序号选名；其他范围仍保持未知，不借当前名称改写。数据库文件名 `history-v1.sqlite` 保持不变，避免产生第二份账本。别名化历史导出仍为 `application-network-history-v2`，应用项新增 `identityOrder`；不导出序号或身份名称。较旧冻结快照缺少该字段时保守视为 legacy-unverified。

过期段每小时按有界目录整体持久标为不可查询，再在单 writer 上逐片回收。过期段ID转存到metadata内有界持久tombstone列表（最多目录上限），先释放物理segments槽位；新段ID避开尚未回收的ID。仅由过期数据引用的身份最多先释放256条、session最多128条，保留仍由未过期段或活动引用的身份。一次维护至多回收一个段的2048条基础记录（活动表优先、每片最多128条）；不会在一次 awaited accept 内循环清空整库。每次源接收的事务边界和5秒 flush tick 可推进一片；有写事务时独立维护不打断它。tombstone 保留到回收完成，重开可继续。整库同时到期时物理回收会跨多次采样，查询已隐藏过期段；这不是即时缩小 SQLite 文件，也不降低1Hz来源或扩大 newest(2) 缓冲。行数预算不等于任意存储故障下的硬实时期限。512MiB库加WAL和提交前预算不变。

XPC 在大小、JSON、协议和 generation 验证后，固定已知业务错误（含 query-busy/request-busy）仅失败当前请求。已认证连接上的单请求超时/取消也不使其他请求失败；取消不声称远端 SQLite 立即停止，晚回复被丢弃。签名/传输、格式、未知错误码、协议或实际响应大小失败撤销连接。新连接与重连共享一次无 key/范围/规则的最小 status 握手，拿到通过签名要求与协议验证的状态后才发业务参数。握手失败/超时保持关门；单个等待者取消不取消别人共享的握手，其等待至多受同一次4秒握手计时约束。

macOS13公开签名要求校验收到的消息，不能把首次出站视为已经验证；见 [Apple DTS 的消息验证说明](https://developer.apple.com/forums/thread/837286) 和 [公开 API 版本说明](https://developer.apple.com/forums/thread/681053)。native transport 的 interruption/invalidation/error 回调立即封闭并在锁外 invalidate，异步 actor 通知之外也检查 transport 状态，防止自动重连继承旧信任。仍保留固定DR与UID边界，不读私有auditToken、不用PID-only身份、不改root服务。

关闭偏好仅代表意图。正常 stop 回复还需校验helper身份并确认sourceState=stopped；成功注销或当前明确未注册也提供停止依据。stop和注销都失败时显示不可用/停止未确认，poll不会根据desired=false推导已停止。新意图revision与断连撤销旧停止、启用、poll和规则回复的更新资格。

## 0.5.4 历史规则、返回上下文与未知峰值

持续上传规则的秒数与 KiB/s 字段保留可往返的小数表示。例如已有规则为 5.5 秒、1.5 KiB/s，打开后不修改再保存会保留原值；旧活动的“当时阈值”也显示该规则的精度，不取整或套用实时速率的舍入显示。既有阈值有效范围不变。

进入应用详情前保留汇总列表的当前页、绝对时间范围、活动筛选、搜索、查询凭证及来源条目。详情内筛选或事件翻页不覆盖原汇总上下文；返回时重新校验原凭证，恢复原页并定位来源应用或活动。校验发现条目/次序变化时显示刷新提示，不混入新的页面。有效上下文中若来源条目不可定位，则将焦点放回汇总操作区。明确刷新或改变时间范围会重置分页和凭证，旧异步查询不能覆盖新结果。只保留当前及原汇总两个有界上下文，不缓存所有页面。

`application-network-history-v2` 中的 `applications`、`curve`、`utcDays` 按每个方向自己的样本数导出真实采样峰值：没有样本是 JSON `null`；有样本且观测为零是数值 `0`；正值保留原浮点精度。某方向缺样不抹去另一方向的峰值。字节总量仍为精确十进制字符串或未知 `null`；字节累计溢出与峰值是否被观察分别判断。预览冻结当前查询，取消不保存文件。数据库格式、采样频率与保留期限不变。

应用汇总按已知上传字节降序排列，已观测零排在正值之后，未知排在所有已知值之后。同量或同为未知时按稳定应用身份排序，不把未知当作零，也不依赖当前身份快照的数据库行号。相同数据和冻结时间范围下，各页次序确定；此保证不等于多次分页查询共享跨写入的数据库快照。


## 0.5.4 持续写入、历史查找与观察状态

### 查询上下文与边界

绝对范围使用整分钟边界。首个查询返回合同 v2：标准化范围、应用选择、搜索、活动类型、匹配活动总数及查询凭证。后续页必须携带同一凭证；每次查询都在一个短只读事务内重新计算按稳定应用 key 排序的成员列表及按 last/id 排序的活动 ID 列表，连同作用域计算 SHA-256。成员或顺序变化即返回 `history.query-context-changed`，界面要求刷新；不会将新页悄悄混入旧查询。数值和代表名称可以反映新提交，凭证不承诺冻结所有数值。没有影响该查询成员/顺序的写入不使其失效。

凭证包含两个 UUID、一个摘要和单调创建时刻，编码不足 512 字节；固定有效期 10 分钟，翻页不续期。executor 重建、helper 重启或在线/离线来源切换会使 generation 不符，或时间到期返回 `history.query-context-expired`。刷新生成新凭证。窗口最多保留当前查询及原汇总上下文，关闭即释放；服务端不维护凭证表或页面缓存，也不为浏览/预览长期持有读事务。只读离线路径用相同实现，缺库不创建库。单次查询约 1 秒预算、应用身份最多 8192 行、活动最多 50000 条、每页最多 64 项、曲线最多 1440 桶、请求 64 KiB 和实际编码响应 4 MiB 的边界保留；完整成员只用于本次有界校验，活动扫描仅保留本页 64 个 ID。

IPC envelope 仍为协议 v1，查询响应新增可选合同字段以保留旧冻结结果的解码能力；实时查询消费者必须确认合同 v2 的范围、选择、搜索、类型、页码及续页凭证一致。旧 helper 即使忽略新增请求字段，其缺合同或作用域不一致的响应也会被拒绝，并提示更新后台或重新连接；不静默降级。这是查询语义兼容检查，不替代现有签名及 helper 身份策略。

### 历史搜索、活动详情和分页空态

搜索由查询层应用于整个绝对范围，包含已退出应用。长度上限为 256 个 UTF-8 字节，去除首尾空白，按保留身份的名称、bundle ID 或安装/可执行路径文本进行不区分大小写的包含匹配。历史库没有逐进程名称数组，不能查询未保存的进程文本。任一保留身份快照匹配后，该稳定 key 的范围内记录一起汇总；旧名称也可定位同一应用。搜索不发送到网络。活动类型只筛活动，不缩小应用总量、分钟曲线或日汇总。

更改/清除搜索保留当前绝对时间范围，回到第一页并新建查询上下文；请求 revision 防止取消后的晚成功/晚错误覆盖新结果。活动详情使用记录的稳定应用 key，同名不同 key 不合并或按显示名跳转。返回恢复来源页、搜索、活动筛选和滚动/键盘焦点。

应用与活动仍共用页码、分别切片。范围内应用总数非零而本页无应用时，说明本页已无更多应用并保留下方活动；不能显示整个范围无历史。有搜索而没有匹配时，显示可清除搜索的提示，不推断该范围没有记录。仅无搜索且应用总数为零时使用保留期限、未采集或不可归属等范围说明。

### 导出作用域及首帧前状态

`application-network-history-v2` / schemaVersion 2 保留原字段并增加 `queryScope`：查询合同版本、随机上下文 ID、应用选择模式/别名、活动类型、搜索是否生效、当前页返回数量、匹配总数及日汇总/覆盖作用域。UTC 日汇总覆盖整个所选范围和匹配应用，与当前页及活动类型独立；来源覆盖计数仍表示整个时间范围，不按应用或搜索裁切。不导出搜索原文、稳定 key、摘要、名称、路径或 bundle ID。旧冻结结果若没有合同，未知作用域字段为 null/unknown，不猜测筛选状态。预览与保存继续使用同一冻结 Data，取消不写文件。process-export v1 字段集合保持不变。

实时应用观察状态独立于采样快照：首帧前区分连接中、待批准、组件不可用、连接失败和已确认停止，nil 不意味着停止。停止仍由现有停止/注销确认决定；状态变化不制造或改写采样时间、sequence 或历史数据。页面保留旧样本时显示其时间并将当前速率置为未知；实时 v1 导出也投影当前观察状态，连接/批准/组件故障映射为 unavailable、确认停止映射为 stopped，当前速率为 null，保留真实样本时间和历史。收到新的成功快照后恢复正常观察状态。

验收分别覆盖实际 Store→Query 写入间隔分页、冷启动 Controller、ViewModel 导航/取消与导出，以及原生窗口。自动化通过不等于正式安装、真实数据库升级、GUI 退出后的后台持续采集或长期资源窗口验收；最终交付与运行结论以各自实际收据为准。


### 最新搜索的繁忙恢复（0.35）

搜索输入先合并 200 毫秒内的变化，只有当前最新 revision 能发出请求。遇到 `history.query-busy` 或 `history.request-busy`，当前请求最多再试 4 次，依次等待 100/200/400/800 毫秒；总等待预算 1.5 秒、最多 5 次请求，每次仍受既有 SQLite/XPC 时限约束。重试沿用该请求的绝对范围和查询凭证，不改采集状态或重启服务。持续繁忙时明确提示点击刷新重试。

每次请求前、错误后、等待结束和结果返回都复核 revision/取消状态。新搜索、筛选、范围、导航、刷新或关闭窗口使旧等待及旧回复失效。客户端取消不宣称远端 SQL 已立即释放；自动重试只处理已定义的瞬时忙状态，其余错误按原义报告。用受控调度验证合并、旧查询占用、最新搜索恢复和永久忙上限；实际 Engine 交错测试同时核对状态读取和采集结算不被查询忙阻塞。
